# dfn-ift-ekf

https://github.com/lorenzo-brancato/dfn-ift-ekf

**How to cite:** see [`CITATION.cff`](CITATION.cff).

Code of the manuscript *Extended Kalman Filtering on the Full Doyle–Fuller–Newman Model via the Implicit Function Theorem* (L. Brancato, A. G. Harej, M. Giglio, F. Cadini; submitted to IEEE Transactions on Control Systems Technology).

The package `dfnekf` is a grey-box DFN model for the LG M50 cell (Chen2020 parameters): diffusion in the particles (12 exponential modes plus a two-term tail) and in the electrolyte is integrated exactly; the kinetics closure (130 algebraic equations) is solved by Newton's method; the step derivative comes from the implicit function theorem. On top of it: an EKF in logit coordinates with a state guard, a square-root UKF on the same model, a UKF on the SPMe (the baseline), the Cramér–Rao bound, the closed-loop experiments of the paper and the learned closure (MIONet) with its residual certificate.

## Install

Python 3.11, versions pinned for the manuscript (`pyproject.toml`):

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[test]"
python -m pytest tests -q
```

The code has no Windows-only calls (thread settings are applied before JAX is imported, see `dfnekf/runtime.py`). The full reproduction reported below was run on Windows 10. On **Linux** (Python 3.11, pinned versions, clean environment built from the source archive) the installation, the tests and a `--quick` run were also verified: the PyBaMM reference of F6Q at th1 regenerates in 49 s and `charge.py --quick` agrees with Windows to about 1e-6. **macOS** has not been tried.

## What is not in the repository

No data and no results are committed (`data/`, `results/`, `*.npz`, `*.pkl` are ignored). The reference simulations (PyBaMM 26.9 DFN, 40/20/40 cells, 300 radial nodes, relative tolerance 1e-9, 1.2 GB) are generated by the first stage. Two small exceptions are committed: the weights of the learned closure (`dfnekf/assets/closure_4to1.pkl`, 1.1 MB) and the data of the figures (`paper/figures/data`, 0.5 MB).

**Learned closure.** The scripts that need the network (`closure_ablation.py`, `residual_stress.py`) load `<results>/closure_4to1.pkl` if the `closure_train` stage has written it, and otherwise the shipped weights, so the repository runs without retraining; `--net FILE` selects another file. To retrain (13 min, 80000 training states from the explicit reference list of `scripts/train_closure.py`): `python scripts/train_closure.py --grid 4:1 --data data --results results/4to1`. The shipped weights are the ones trained in the M18 reproduction; retraining uses the same seed and list, but floating-point results can differ between machines, so the shipped file is the reference for the numbers of the paper.

## Reproduce

Every script takes explicit `--grid`, `--data` and `--results` arguments: no environment variable chooses the grid. The runner executes the stages in order, with at most `--procs` processes (one thread each), and resumes an interrupted run (marker files in `results/.done`):

```bash
python scripts/run_all.py --list
python scripts/run_all.py --stage refs,ageing_ref,model,static,protocols,twin,closure_train,closure --procs 6
python scripts/run_all.py --stage ageing --procs 2           # the two trackers, 15.7 h each, in parallel
python scripts/run_all.py --stage timing --procs 1           # only on an otherwise idle machine
python scripts/run_all.py --stage aggregate --procs 2
python figdata/make_figdata.py --results results/4to1 --out paper/figures/data --compare <folder with the published figures/data>
```

`--stage ukf` (30 runs of the full UKF, about 100 min of wall time each with five running at once) and `--stage ukf_pilot` (four runs with 4 Newton iterations per sigma point, 8.7 h each) run only when named; the UKF results in the paper are for one Newton iteration per sigma point (`--closure-iters 1`, the default).

### Auxiliary scripts

Two scripts support the pilot of Appendix B (why the full UKF solves the closure with one Newton iteration per sigma point). They are not stages of the reproduction proper:

- `scripts/ukf_closure_check.py`: residual of the closure at the 2N+1 sigma points of the UKF run with one iteration, and the residual and cost of 1 to 6 iterations and of Newton to convergence at the same points.
- `scripts/ukf_pilot.py` (stage `ukf_pilot`): four UKF runs at th2 with four iterations per sigma point against the one-iteration runs; it is a result of its own (see `release/VERIFY_M18.md`).

### Further checks and the CV freeze (not stages of `run_all.py`)

- `scripts/review_checks.py` (`--parts spme,sei`; `--parts freeze` reads a run of `ageing_track.py`): Appendix D, the SPMe in open loop with the true parameters on the charge protocol (phi_pl error and 0 mV crossings without any estimation, parameter errors of both filters at the end of the P6L blocks); Sec. III-D, the lithium-consuming SEI side-reaction current added to the open-loop model removes 13 % of the model error in the CV hold of RPT 3-6. `--quick` runs a short version of each part.
- `scripts/ageing_track.py --freeze {none,voltage,phase}` (default `none`, the paper's run, bit for bit): the CV freeze of Sec. III-D. `voltage` zeroes the parameter rows of the Kalman gain where the *measured* voltage is at least `--freeze-above` (4.195 V) in charge, the first remedy tried; `phase` does so during the constant-voltage segment of every RPT, taken from the protocol schedule as a BMS knows its charger state; `--cv-update none` removes the measurement update in that segment altogether (prediction only). `--cv-scope all` extends `phase` to the CV of the ageing cycles. Outputs carry the suffixes `_freeze-voltage`, `_freeze-phase`, `_freeze-phase-noupdate`.
- `scripts/freeze_cv.py`: evaluates those runs (criteria at the read-outs before the CV, at its end and at the end of the RPT, hour up to which all estimates pass, change of the estimates during and after the CV) and writes `trk_rf_<variant>.csv` in the format of `paper/figures/data/trk_rf.csv`. Results and discussion: Appendix C of the paper.
  The three variants of the freeze experiment: *control* (`--freeze none`, the paper's run); *P1* (`--freeze phase`: in the CV segment of every RPT the parameter rows of the gain are zero, the cell state is still updated and the parameter covariance is not reduced); *P2* (`--freeze phase --cv-update none`: no measurement update in that segment, prediction only for state and covariance). The freeze follows the protocol phase, never the measured voltage. Each run takes about 21 h on one core.

### Timing the filter

Run `--stage timing` with no other process on the machine (the scripts write the number of busy processes in the header). **Do not pin the process to a core** (`taskset`, `SetProcessAffinityMask`, `dfnekf.runtime.pin_to_core`) when timing: XLA's helper threads share the pinned core and the step at N = 653 doubles (15.6 ms against 7.0 ms). `pin_to_core` is kept for long accuracy runs only.

Reference machine of the runs reported here: Intel Core i7-9700 (8 cores, 3.0 GHz), Windows 10, Python 3.11.15, jax/jaxlib 0.10.2, one thread. Measured unpinned on this machine: EKF step 6.97 ms at N = 653 (0.61 ms at N = 168, 11.2 ms at N = 813); full UKF 283 ms; UKF on the SPMe 0.30 ms. The manuscript prints 7.9, 0.64, 11.9, 287 and 0.279 ms. **Timings of the same step, remeasured in other sessions, vary by up to 12 % (here 6.97 against 7.9 ms for the EKF at N = 653); the manuscript reports the original measurement** and `paper/figures/data/cost_*.csv` holds it. `figdata/make_figdata.py` regenerates these two files from your own measurement; the value labels of Fig. 4 are read from them, so points and labels stay consistent.

| `tests/` | Jacobian (IFT against `jacfwd`), lithium conservation, grid geometry, stored values, shipped closure weights, CV-freeze codes |
